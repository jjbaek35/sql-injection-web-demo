SQL INJECTION WEB SECURITY DEMO - LINUX INSTALLATION
===================================================

PURPOSE
A five-minute, localhost-only SQL injection authentication bypass demo
with a parameterized-query comparison.

REQUIREMENTS
- Ubuntu, Debian, Kali Linux, or similar
- Python 3.9+ and its built-in sqlite3 module
- python3-venv, python3-pip, Git, and a local web browser
- No separate SQL server or SQLite installation is needed.

1. INSTALL PREREQUISITES (DEBIAN/UBUNTU/KALI)
   sudo apt update
   sudo apt install -y git python3 python3-venv python3-pip

2. CLONE THE REPOSITORY
   git clone https://github.com/jjbaek35/sql-injection-web-demo.git
   cd sql-injection-web-demo

3. CREATE AND ACTIVATE THE VIRTUAL ENVIRONMENT
   python3 -m venv .venv
   source .venv/bin/activate

4. INSTALL PYTHON DEPENDENCIES
   python -m pip install -r requirements.txt

5. START THE SERVER
   python app.py

6. OPEN THE DEMO PAGES IN A BROWSER ON THE SAME MACHINE
   http://127.0.0.1:5000/vulnerable
   http://127.0.0.1:5000/secure

7. STOP THE SERVER
   Press Ctrl+C. To leave the environment, run: deactivate

OPTIONAL SQLITE CHECK
   python3 -c "import sqlite3; print(sqlite3.sqlite_version)"

TROUBLESHOOTING
- ModuleNotFoundError: No module named 'flask'
  Activate .venv and rerun the pip install command.
- Address already in use
  Stop the program currently listening on port 5000.
- SQLite objects created in a thread can only be used in that same thread
  Use this repository's app.py, which sets check_same_thread=False and
  serializes database calls with a lock for this local teaching demo.
- The browser cannot connect
  Confirm the Python process is running on the same machine as the browser.

SECURITY WARNING
This app contains an intentional SQL injection vulnerability, visible
sample credentials, and plaintext passwords. It must run ONLY on
127.0.0.1 in a controlled classroom environment, never on a public
interface or with real account credentials.
